## 1. 背景与目标

当前工作站位置相对固定，但上层动作在每个普通位姿、关节位姿、笛卡尔段和倒料摆动步骤中都调用 MoveIt 重新规划。一次动作失败还会刷新状态并再次规划。这导致节拍慢、结果存在随机性、调试链路复杂。

本次重构目标如下：

1. 固定工位动作在生产运行时不再逐步调用 MoveIt 规划。
2. 把经过校验的轨迹预编译并缓存，运行时直接通过 `FollowJointTrajectory` 执行。
3. 支持普通关节运动和严格笛卡尔直线运动；抓取、放置、取出和退出的近端段必须可声明为垂直直线。
4. 点位与路线只有一个数据源，支持方便地新增、修改、删除、记录当前位置、校验和重载。
5. 速度倍率可在运行时调整，不重新规划；速度变化必须遵守关节速度、加速度和最短时间约束。
6. 当前默认使用固定位置，不依赖激光；保留可切换的传感器修正适配层，未来启用时不推翻运动架构。
7. 保留现有光谱检测状态机的业务约束，但消除重复运动实现和多个节点同时抢占控制器的问题。
8. 建立 Git 基线、测试、运行手册、回滚方式和长期工程约定。

## 2. 已完成的代码与环境审计

### 2.1 运行环境

- 远程主机：Ubuntu 22.04，ROS 2 Humble。
- MoveIt：2.5.9。
- ros2_control：2.53.1；ros2_controllers：2.52.1。
- 控制器：`joint_trajectory_controller/JointTrajectoryController`，更新频率 100 Hz。
- 机械臂动作接口：`/arm_controller/follow_joint_trajectory`。
- 工程当前不是 Git 仓库；当前源码、文档和资源约 91 MB。
- 审计时未发现工作站 ROS/机械臂进程在运行。

### 2.2 当前主要模块

- `panthera_hardware`：ros2_control 硬件接口，连接 Panthera SDK。
- `panthera_ht_config` / `panthera_ht_ros_description`：URDF、SRDF、MoveIt 和控制器配置。
- `panthera_task_framework`：YAML 工作流执行器；每个运动步骤都现场规划。
- `panthera_spectrometer_cell`：光谱工作站长期运行状态机；`RobotActions` 内再次实现整套 MoveIt 动作。
- `panthera_pose_tuner`：点位调试器；点位在 C++ 中硬编码，与主 YAML 重复。
- `panthera_web_hmi`：Web HMI；可以修改已有点位，但不能真正新增或删除点位。
- `panthera_rs485` / `panthera_io`：激光、RS485 状态和可选数字 IO 适配层。

### 2.3 主要问题

1. `workflow_executor_node.cpp` 的 `move_pose`、`move_named`、`move_joint` 每次调用 `plan()`；笛卡尔段每次调用 `computeCartesianPath()`。
2. `RobotActions.cpp` 对所有 `moveJ`、Cartesian、倒料和摆动重复规划，且最多重试两次。
3. 点位散落在 `spectrometer_cell.yaml`、`cup_pick_place_workflows.yaml` 和 `TuningTargets.cpp`，存在坐标漂移风险。
4. 默认启动链同时运行工作流执行器和光谱状态机，两者都可向机械臂发命令，没有单一运动所有者。
5. `trajectory_execution.allowed_start_tolerance` 当前为 `10.0`，无法作为可靠的起点一致性保护。
6. 状态机同步阻塞执行完整动作，状态机 tick、软件超时和暂停不能在动作执行期间及时介入。
7. 真实模式下状态机固定执行两次激光测量；目前无法选择“固定位置模式”。
8. HMI 用文本替换方式改 YAML，只允许已存在名称；不能检查删除引用，也不能编译/验证整条路线。
9. 配置目录中有大量运行时 `.bak_*` 文件；未建立版本控制后容易把备份与正式配置混淆。
10. 真实急停、真实出料信号和真实光谱仪完成信号尚未完成硬件闭环；当前部分接口仍是人工服务或 TODO。

## 3. 目标架构

采用“离线/重载时编译，运行时直接执行”的两阶段架构。

```text
HMI / 状态机 / 调试工具
          |
          v
  唯一 Motion Server
  - 点位与路线仓库
  - 编译、校验、缓存
  - 起点检查、互斥、取消
  - 运行时速度缩放
          |
          v
/arm_controller/follow_joint_trajectory
          |
          v
 ros2_control -> Panthera 硬件
```

MoveIt 不从工程中删除，而是降级为工程工具：

- 新增或修改点位/路线时做 IK、碰撞、关节限位和路径连续性检查。
- 编译笛卡尔直线段。
- 手动调试和新工位验收时提供可视化检查。
- 固定生产循环运行时不调用 OMPL/Pilz 做逐步全局规划。

### 3.1 单一运动所有者

新增独立运动包（暂定名 `panthera_motion`）。只有该节点可以向机械臂轨迹控制器发目标。其他包通过 action/service 调用它：

- 光谱状态机只负责任务顺序、工艺条件和错误恢复。
- 工作流包只负责编排路线、夹爪、等待和 IO。
- 点位调试器改为运动服务的调试客户端，不再自己持有 `MoveGroupInterface`。
- 默认启动链禁止同时存在多个直接运动发布者。

### 3.2 运动接口

新增可取消的 action，至少包含：

- 请求：路线名、速度倍率、dry-run、可选参数修正。
- 反馈：当前段、总段数、当前点、完成百分比、当前误差。
- 结果：成功/失败、错误码、消息、实际耗时。

配套服务：

- 重载并编译运动目录。
- 列出点位、路线和引用关系。
- 记录当前关节/TCP 为新点位。
- 校验单点、单段或整条路线。
- 设置全局速度倍率。
- 取消当前动作并进入保持状态。

## 4. 单一数据源设计

新增机器可管理的运动目录文件，建议路径：

```text
src/panthera_motion/config/motion_catalog.yaml
```

### 4.1 点位

每个点位有稳定 ID，并同时保存对人友好的 TCP 信息和确定执行所需的关节信息：

```yaml
points:
  outlet_1_grasp:
    frame: base_link
    tcp_xyz: [-0.030, -0.440, 0.160]
    tcp_rpy: [0.0, 0.0, -1.5708]
    joints: [j1, j2, j3, j4, j5, j6]
    tags: [outlet_1, grasp]
```

规则：

- `joints` 是生产执行的确定起点/终点。
- `tcp_*` 用于显示、编辑、IK 复核和笛卡尔段定义。
- 通过“记录当前位置”创建的点同时记录关节值和 TCP。
- 通过编辑 TCP 创建的点必须经过 IK 编译并由操作者确认分支。
- 删除被路线引用的点必须拒绝，并返回引用列表。

### 4.2 轨迹段

至少支持：

- `joint`：关节空间移动，可包含一个或多个避障中间关节点。
- `linear`：TCP 直线段，按固定步长采样，姿态保持或插值。
- `gripper`：夹爪开/合。
- `wait`：确定时间等待。
- `signal`：等待 IO/RS485/工艺信号。
- `motor`：清洁电机等工艺输出。

抓取相关 `linear` 段可声明约束：

```yaml
constraints:
  vertical_axis: z
  max_lateral_error_m: 0.001
  keep_orientation: true
```

编译器在保存/重载时检查起点和终点 X/Y 偏差、采样后 TCP 横向误差、姿态误差、关节跳变和限位。任何一项失败，旧版本缓存继续有效，新配置不得投入运行。

### 4.3 路线

路线引用点位和轨迹段，不复制坐标。按夹爪/工艺动作将连续机械臂段组合为较少的控制器 goal，避免每个小点停顿。

需要迁移的正式路线至少包括：

- 出料口 1/2 取杯。
- 固定光谱仪放杯、取杯。
- 清洁、倒料、毛刷动作。
- 出料口 1/2 放回。
- 等待位、回安全位和恢复路线。

## 5. 轨迹编译与执行算法

### 5.1 关节段

1. 从目录读取起点、终点和可选中间关节点。
2. 检查所有值有限、维度正确并在 URDF/SRDF 关节限位内。
3. 检查相邻点跳变和配置的最大单段距离。
4. 使用 MoveIt RobotState/PlanningScene 做离线碰撞检查；固定环境下由验收结果锁定。
5. 使用时间参数化生成位置、速度、加速度和时间戳。
6. 保存内存缓存，并输出可审计的编译摘要/哈希。

### 5.2 笛卡尔直线段

1. 以已记录的起点关节值作为 IK 种子。
2. 以 2~5 mm 可配步长在 TCP 空间插值；抓取段默认保持姿态不变。
3. 每个采样点用前一采样点作为下一次 IK 种子，保持同一 IK 分支。
4. 对每个样本检查 IK、关节限位、自碰撞、环境碰撞、关节跳变。
5. 对垂直段额外计算 TCP 重建误差，保证 X/Y 横移不超过阈值。
6. 对整段做时间参数化并缓存。
7. 编译失败时给出具体点位、采样序号和原因，不允许部分生效。

### 5.3 运行时起点保护

每次发轨迹前：

1. 获取新鲜 `/joint_states`。
2. 检查机械臂已停止或速度低于阈值。
3. 比较当前关节值与缓存轨迹首点。
4. 小误差在严格容差内可执行；超限则拒绝。
5. 若配置允许恢复，只能执行一条单独验收过的“当前位置到安全接入点”路线，不能静默拼接或重新规划。

建议初始关节起点容差为 0.03~0.05 rad，最终值需根据真实编码器噪声和重复定位数据确定。

### 5.4 速度控制

- 编译时以 1.0 基准速度生成受限轨迹。
- 运行时倍率作用于时间、速度和加速度：时间除以倍率，速度乘倍率，加速度乘倍率平方。
- 再次检查缩放后不超过每关节配置限值。
- 默认生产倍率、调试倍率和每段上限分开配置。
- 动作执行中是否允许即时变速取决于控制器能力；第一阶段只允许下一段/下一次 goal 生效，避免中途重发造成跳变。

## 6. 固定模式与未来传感器模式

引入明确的位置来源配置：

```yaml
positioning:
  mode: fixed       # fixed | sensor_offset
```

### 6.1 当前固定模式

- 不启动激光节点也能完成完整循环。
- 光谱仪使用固定点位和固定路线。
- 状态机不等待激光新鲜度，也不因激光服务缺失进入 ERROR。
- HMI 明确显示“固定位置模式”。

### 6.2 未来传感器修正模式

- 保留 `panthera_rs485` 激光驱动和统一传感器适配接口。
- 传感器只产生经过标定、限幅和新鲜度检查的位姿偏移。
- 偏移仅作用于被声明为可参数化的点或局部直线段。
- 修正后重新做局部 IK、碰撞和连续性校验；失败立即拒绝，不回退到未校验运动。
- 当前的两次测量语义（放杯前、取杯前）保留在状态机业务上下文中，但 fixed 模式直接返回固定标称值/零偏移。

## 8. 状态机与流程重构

### 8.1 保留

- 两个出料口独立状态和任务排队。
- 杯子必须放回原出料口。
- 放杯前/取杯前位置上下文。
- 检测开始、完成、错误和恢复状态。
- 急停最高优先级、错误保持上下文、复位后人工恢复。

### 8.2 修改

- `RobotActions` 不再拥有 MoveGroup；改为 Motion Server action 客户端。
- 状态机动作改为异步提交和轮询反馈，tick 不再阻塞。
- 软件动作超时能够真正取消 goal 并进入 ERROR。
- 暂停、停止、急停请求能够在动作执行中取消控制器 goal。
- 固定模式跳过传感器等待，传感器模式沿用两次测量语义。
- 工作流执行器和专用状态机共享同一 Motion Server，不能直接发控制器命令。

## 9. 安全整改

在任何真实运动前完成：

1. 将 MoveIt 起点容差从 `10.0` 改为合理值；Motion Server 自己实施更严格检查。
2. 控制器 action 使用明确 path/goal tolerance 和合理 goal time。
3. 默认启动链只允许一个 Motion Server 持有机械臂 action。
4. 急停时取消 action、调用控制器停止/保持，并验证硬件急停链路；软件按钮不作为硬件急停替代品。
5. 对点位配置中的异常单位和姿态逐项复核。
6. 所有首次真实执行使用低速、单段、无人进入工作空间、可立即硬停的条件。
7. 禁止未经确认直接执行从任意当前位置到固定轨迹首点。
8. HMI 的真实执行与写配置操作继续受服务端状态检查保护。

已发现需现场确认的高风险配置：

- `named_poses.clean_brush.rpy[0]` 当前为 `30.0`，文件约定单位是 rad；需要确认实际意图是否为 30 度（约 `0.5236 rad`）。
- 光谱仪修正轴在不同文档/代码中出现 X/Y 不一致；当前主 YAML 为 `axis: x`，启用传感器前必须重新确认。
- 当前真实急停输入尚未接入状态机；只能在接线和接口确认后做闭环验收。

- `RobotActions` 改为 action 客户端。
- 状态机改成非阻塞动作反馈。
- 工作流执行器、点位调试器改为统一客户端。

完成标准：任何时刻只有 Motion Server 能控制机械臂；暂停/停止/超时可取消动作。

### 阶段 F：HMI CRUD 与运维文档

- 实现点位/路线 CRUD、记录当前位置、引用检查、编译和原子保存。
- 显示固定/传感器模式、速度倍率和运动状态。
- 更新一键启动、停止、备份和恢复说明。

完成标准：不改 C++ 即可安全新增、修改、删除点位和路线。

### 阶段 G：真实机械臂分级验收

1. 只读连接与控制器状态检查。
2. 编译/dry-run，不发运动。
3. 低速执行安全点和单个关节段。
4. 低速执行单个垂直 Cartesian 段，测量横向误差。
5. 无物料完整空跑。
6. 单杯分段运行。
7. 单杯完整循环。
8. 多轮循环、暂停、取消、超时、进程重启和断传感器测试。
9. 提升到生产速度并记录节拍对比。

每一级失败必须停在当前级别，修复并重新通过，不能跳级。

## 11. 测试计划

### 11.1 自动测试

- YAML schema、重复 ID、缺失引用、删除引用测试。
- 非有限数、维度、关节限位、跳变测试。
- IK 成功/失败、分支连续、碰撞测试。
- 垂直段横向误差和姿态保持测试。
- 速度缩放后速度/加速度限位测试。
- 起点容差、新鲜 joint state、运动中重载拒绝测试。
- action 成功、拒绝、取消、超时和控制器错误测试。
- fixed 模式无激光完整状态机测试。
- sensor 模式传感器新鲜、超限、丢失和偏移编译失败测试。

### 11.2 集成测试

- `colcon build --symlink-install` 全工作区构建。
- `colcon test` 与结果汇总。
- 模拟状态机连续两出口任务。
- HMI CRUD + 编译 + 回滚测试。
- 启动链检查，确认只有一个运动所有者。

### 11.3 真实验收指标

- 生产循环中 MoveIt 全局规划调用次数为 0。
- 相同起点和同一版本路线输出的关节轨迹一致。
- 抓取/放置直线段横向偏差满足配置阈值。
- 速度倍率切换不超关节限值且下一段生效。
- 取消/急停请求能在规定时间内停止或保持。
- 固定模式在激光节点未启动时可正常完成循环。
- 重载失败不影响上一版已编译轨迹继续使用。
- 与当前实现相比，节拍有可测量改善；最终目标值由现场基线数据确定。

## 12. Git、发布与回滚

- 建立初始基线提交后按阶段小步提交。
